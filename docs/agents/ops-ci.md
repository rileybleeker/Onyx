## Testing and CI

- **CI model (Riley, 2026-11-15): no automated tests before deployment; test afterward.** The existing required `offline-checks` performs Python syntax validation only (not a test pass), preserving branch protection without a settings change. Build, authentication, authorization and signing checks remain. Do not run automated tests before deployment, including locally. Independent source review precedes publication. The credential-free suite runs after a successful exact-revision Production deployment and on the 30-minute schedule; production smoke remains postdeploy. Never introduce writes to real user data for automatic tests. Existing live write tests require their separate explicit manual opt-in. See `docs/ci-cd.md`.
- **Type-check the frontend before you open a PR (Riley, 2026-11-15).** For any change under `frontend/`, run `npx tsc --noEmit` in `frontend/` (2–15 s; run `npm install` first if the worktree has no `node_modules`) and fix every error before opening the PR. It is the same check the scheduled suite's `frontend-types` job runs, not an automated test, so the rule above does not forbid it. No PR check runs tsc, and the Vercel Production build skips type checking (`typescript.ignoreBuildErrors` in `frontend/next.config.ts`, since 2026-11-14), so a type error otherwise deploys to production and surfaces only when `frontend-types` in `.github/workflows/scheduled-tests.yml` goes red against master, which then needs a fix PR. A compile error (bad syntax, a missing import) still fails the Production build, and `post-merge.yml` then reverts the commit or halts the merge train (`docs/ci-cd.md`). (Corrected 2026-11-16: this said the Production build runs the type check.)

## Delivery accountability (Riley, 2026-11-15)

- For authorized implementation, use headless Claude Code handoffs with bounded scope and acceptance criteria. **Codex reviews only AFTER merge and never before (Riley, 2026-11-17).** It reviews the merged, deployed revision and sends the fixes to make as items in the dev backlog; Claude builds those like any other backlog item. Pre-merge checks are the builder's own `npx tsc --noEmit` for frontend changes and the repo's CI checks; no Codex review runs before merge. Hold a PR only for a required migration not yet applied (apply it first), a decision that is Riley's, or an investigation-only change; that hold list applies once the required builder prerequisites have succeeded, and a failed prerequisite (for example a failing `npx tsc --noEmit` for a frontend change, or a failing repo CI check) is fixed before the PR goes forward. Two different Codex roles must not be confused: the builder's own in-workflow Codex CLI consultation is pre-merge, part of the builder workflow, and never a merge gate; the independent post-deploy Codex advisor runs only after deployment, files its findings as dev backlog items, and is never a merge approval gate. A builder's summary or exit code is not a review.
- **Launched, code written, reviewed, merged, deployed and verified are distinct states.** Record the task, attempt, exact revisions, evidence and next action. Never mark Done from launch, a model's claim, a merge, or a successful `/login` response alone.
- The orchestrator owns supervision through verified completion or an explicit blocker, without Riley having to remind it. Persist recovery state before long-running work; use bounded retries and reconcile existing work after restart instead of launching duplicates. Notify Riley of essential blockers and required decisions.
- Use one writer per task/worktree and one owner per release transition; respect existing locks and branch ownership. A changed head invalidates its review/check receipts. Preserve private receipts and recovery history across chats and restarts; never invent missing evidence.
- Verify the actual production behavior against acceptance criteria. For relevant UI changes, include the authenticated **Today entry point, desktop and phone widths**, and the affected interaction. Distinguish a deployed revision from observed product acceptance; record unavailable checks as gaps, not passes. The testing policy above still applies.
- Follow [delivery accountability](../delivery-accountability.md). Existing worker mechanics live in [personal-agents feature-worker documentation](https://github.com/rileybleeker/personal-agents/blob/main/docs/feature-worker.md); these requirements do not assert that every supervision or recovery mechanism is already implemented.

## Audit and review findings

- **Audit and review findings are settled against the data, never against docs or tests (2026-11-10).** A finding that claims wrong results may be closed as refuted only by a check on live data or by running the code. AGENTS.md, the `docs/agents/` files, the audit CONTEXT files and the existing tests are what such a finding disputes, so they are not evidence against it. Anything left DISPUTED or unverified when an audit or review ends becomes a roadmap row in the same session (Tasks DB, `Source = "Onyx Roadmap"`) at the audit's severity (P0 → `Critical`, P1 → `High`), with what would settle it in Notes. The weekly-review agent lists open Critical Onyx rows every week (personal-agents `agents/weekly-review.md`, step 3c). Origin: the one-night HRV misalignment (hrv-pipeline.md, "Alignment and dates") was flagged P0 on 2026-05-27, marked DISPUTED because it contradicted AGENTS.md and `tests/test_phase2_alignment.py` (a synthetic frame that never reads the real matrix), never got a row, and ran for five and a half months. A pipeline whose results depend on an assumption about another layer (what a matrix row means, which day a date column describes) checks that assumption at run time and writes a `failed` or `partial` heartbeat whose `error_message` starts with `GUARD <name>:`; the devops agent matches that prefix and tells Riley instead of re-running.

## Smoke testing (Playwright)

Production tripwire for the class of bug `tsc` + `lint` cannot catch: a panel that **should** have data silently falling back to its empty state. The Spotify FK-ordering, HRV `JSON.parse`-of-jsonb, and supplements renamed-column regressions all shipped green and only surfaced when Riley clicked around production — each as an empty/broken panel.

- **Core principle:** *empty-state fallback present where data should exist = test failure.*
- **What it covers:** loads every dashboard page against **real production data** (authenticated) and asserts (a) the page isn't bounced to `/login` and doesn't hit the Next.js client error boundary, (b) a real data element rendered (recharts data marks / table rows / journal list items), and (c) **known empty-state fallback strings are ABSENT**. Two pages get precise assertions: `/analytics/hrv` (HRV Correlates draws bars + none of the "…not yet computed" / "Run hrv_analysis.py to compute correlations" fallbacks) and `/supplements` (the "Today's compound totals" table is populated whenever `/api/supplements/today` reports intakes — the test self-skips on a legitimately empty day rather than false-fail). Strings that can be legitimately empty (ReccoBeats-thin Spotify subsets, manual-entry meal/weight sections, range-windowed lists) are intentionally **not** asserted.
- **Files:** `frontend/playwright.config.ts` (single chromium project, `retries:1`, reuses a saved `storageState`), `frontend/e2e/auth.setup.ts` (logs in once via `/login`, saves `e2e/.auth/state.json` — gitignored), `frontend/e2e/smoke.spec.ts`. The `e2e/` dir + `playwright.config.ts` are excluded from `tsconfig.json` so they don't affect `next build`.
- **Run locally:** `cd frontend && npx playwright test` (add `--ui` to watch / debug). Defaults to the prod Vercel URL via `SMOKE_BASE_URL`.
- **Required env** (3 vars) — read from `frontend/.env.local` locally and from **GitHub repo secrets** in CI: `SMOKE_TEST_EMAIL`, `SMOKE_TEST_PASSWORD`, `SMOKE_BASE_URL`. (The login uses Supabase Auth email+password; use a real app account.)
- **Scheduled-workflow keepalive:** GitHub auto-disables every cron workflow after 60 days without a push (happened 2026-09-18 → 2026-10-03 outage). `.github/workflows/keepalive.yml` runs Mondays 12:00 UTC and re-enables every workflow via the Actions API, which resets that clock without a dummy commit. If Onyx goes quiet, `gh workflow list --all` and look for `disabled_inactivity` first.
- **CI:** `.github/workflows/smoke-test.yml` runs every 6h (`0 */6 * * *`) + `workflow_dispatch`. A failure = red X + GitHub's failure email (the alert); CI keeps no Playwright trace, screenshot or HTML report and uploads no artifact (the repo is public and those hold signed-in pages); reproduce a failure locally with `npx playwright test`, where traces and screenshots stay on. **Provenance (DEL-02, 2026-11-16):** a post-merge run counts for a commit only when the signed-in `/api/version` (commit + `VERCEL_URL`) shows that commit and deployment before and after the tests (`e2e/provenance.ts`); anything else is `deferred` (pending verification), never a pass, and post-merge reverts only a commit that failed twice on its own deployment while its parent's `post-merge/smoke` commit status passed in the 3 h before that failure, and a revert or halt is dropped only by an exact smoke pass whose run started after the failing attempt ended (attempt times from the smoke runs themselves, kept in each receipt, never when a receipt was written). `post-merge/smoke` is written only while the repository variable `SMOKE_RECEIPT_STATUS` is `on` (until then every smoke failure halts, never reverts); once written it is part of master's combined commit status, so the deploy result is the `Vercel` context, never the combined `state`. The 6-hourly run tests the newest deployed master commit, matched on the commit, and goes red when it could not confirm what production serves (rules in `docs/ci-cd.md`).
- **Adding a page:** append to the `PAGES` array (or add a dedicated `test.describe`) in `smoke.spec.ts`. For a manual-entry page whose own in-window empty-state is legitimate (e.g. `/caffeine` after a logging pause), set `legitimateEmpty` to that exact string — the test then SKIPs with a reason instead of failing; `/caffeine` additionally honours `?days=N` (7–730; the ISR seed is discarded for non-default windows) and a dedicated test loads `/caffeine?days=720` to assert the intake chart draws from real historical rows; note the shared Sidebar sparkline is a recharts svg, so the generic "charts" probe alone cannot tell "page empty" from "chart broke". Prefer text-absence of the real empty-state string + a "some data element exists" check over brittle per-element selectors.
