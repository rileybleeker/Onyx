- **Reading module (`/reading`, 2026-11-07) — a gamified reading log with highlight + comment capture and a Notion mirror.** Tables in `sql/reading_schema.sql`: `pds.books` (slug, total_chapters, start/target_date, status, `notion_page_id` = the per-book reading-log page, `habit_name` = the habit stamped on session days), `pds.reading_sessions` (behavioral `session_date`, chapter range, minutes, medium, `recall` = the from-memory note, `question`), `pds.book_highlights` (passage + `comment` + `concept` tag + source, UNIQUE on (book, passage) for idempotent Kindle re-imports, SM-2-lite fields `ease`/`interval_days`/`next_review`), `pds.reading_reviews` (grades), `pds.reading_quizzes` (checkpoint scores). **Everything gamified is derived, never stored** (`lib/reading.ts:computeOverview`): XP (10/chapter, 20/recall ≥40 chars, 5/commented highlight, 15/review day, 10/quiz point, 50/on-time checkpoint), levels every 100 XP with titles from `pds.books.theme` (generic when a book has none), streak over behavioral days, pace vs the linear start→target line, checkpoints at 30/65/100% of the book, 10 badges. ## Personal journal (Notion Entries)

- **`pds.journal_entries` is the personal Notion journal — distinct from `pds.journal` (the WHOOP+habit *behavior* view).** Notion DB "Entries" (ID `96541038264d45aba2a9601d9b175a7e`, parent page "Journal"). One row per Notion page; PK = `notion_page_id`. Properties: `entry_date` (ET-naive — Notion's Date property has no time component), `title`, `mood` (low/neutral/good/great), `source` (voice/remarkable/typed), `confidence` (high/medium/low), `topics` (JSONB array), `content_md` (page body as markdown), `word_count`, `embedding` vector(1024) from Voyage `voyage-3-large`, `archived` (soft-delete). Skip-if-unchanged guard: `notion_edited_at` — ETL only re-fetches blocks / re-embeds when Notion's `last_edited_time` advances. Indexes: B-tree on `entry_date` + `mood`, GIN on `topics`, HNSW (cosine) on `embedding`. RPC `pds.search_journal_entries(query_embedding, date_from, date_to, mood_filter, topic_filters, result_limit)` exposes filtered + similarity-ordered search to the chat tool. **Not auto-joined into `daily_health_matrix`** — same isolation principle as Spotify; cross-analysis happens at query time only. Notion is single write surface (read-only direction, unlike habits which is bidirectional). The app has two journal writers, both following the rules below and writing to Notion, never to the table: the /check-in journal draft (`POST /api/journal/entry`, 2026-11-14; every label reviewed by Riley and sent) and the /log **Journal** section (`POST /api/journal/file`, 2026-11-15, `lib/journal-file.ts` + `lib/journal-file-server.ts`; see "Log screen"): the body exactly as sent, Date = today in New York, Source as sent, and any of Title / Mood / Confidence / Topics left blank filled by ONE structured-output model call (`claude-sonnet-5-5`, effort low) that returns only those four labels (it never sees a way to change the body); a repeat of the same day and words within 15 minutes returns the page already there (Notion query on Date + created_time, then the page's paragraphs compared with the body). Both share the Notion calls in `lib/journal-file-server.ts`; neither logs the text. Sync via `journal_etl.py` hourly at `:35`. A Notion-hosted image is stored in `content_md` as `![caption](notion-image:<block id>)`, never as its download URL (signed, dead after about an hour); the embedding text carries only `[image: caption]`. Rows that were re-embedded and rows that were not are upserted in separate requests (`uniform_batches`; see the bulk-upsert rule under Conventions). Test: `tests/test_journal_etl.py`. Journal DB must be shared with the "SMS Reminders" Notion integration (same blocker as initial habits deployment — `project_onyx_habits.md` memory).

  **When creating a journal entry in Notion (e.g. forwarding a Claude conversation Riley dictated):** the `notion-create-pages` call **must** populate all four metadata properties — `Source`, `Confidence`, `Mood`, `Topics` — plus `Title` and `Date`. Never create a journal page with any of these unset. Parent: `{ type: "data_source_id", data_source_id: "de49562b-652b-4e95-94b1-085dc7ce8c99" }` (the Entries data source under the Journal DB).

  **Field rules** — these mirror the canonical version in the **"Reminders/Habits/Journal Entry"** Claude.ai Project, which is the source of truth for the mobile/web Claude flow. **When changing the rules here, also update that Project's custom instructions to keep both surfaces in sync.**
  - **`Source`** (select: `voice` | `typed` | `remarkable`). DEFAULT `voice` — anything originating from a Claude conversation. Override to `typed` only if the user explicitly says the entry's origin was typed text; `remarkable` only if it came from their reMarkable tablet.
  - **`Confidence`** (select: `high` | `medium` | `low`). Measures the **user's certainty about the entry's content** (NOT transcription confidence — repurposed 2026-05-24; the Notion property description was updated to match). DEFAULT `medium` whenever the entry doesn't clearly signal certainty — never leave blank. `high` for explicit conviction ("I know…", "definitely"); `low` for hedging ("I think maybe…", "could be wrong").
  - **`Mood`** (select: `low` | `neutral` | `good` | `great`). Infer from content; never leave blank. low = negative affect, neutral = informational/flat, good = positive affect, great = strong positive. If torn between adjacent values, pick the lower one.
  - **`Topics`** (multi-select). Prefer existing tags when one fits — current list: `work, relationships, dating, health, gym, running, alcohol, sobriety, mental-health, family, travel, reflection, goals, finance, sleep`. New tags are allowed only when none of the existing ones reasonably fit (don't add "fitness" when "gym" or "running" applies; don't add "anxiety" when "mental-health" applies). At least one tag per entry.
  - **`Title`** (title): short, specific, 3–8 words. Scannable in a list. Avoid generic titles like "Journal Entry" or "Note".
  - **`Date`** (date): today in `America/New_York`, date-only. Override if the user names a different date ("yesterday", explicit date).

  **Body — VERBATIM RULE.** The page body MUST be the user's raw text exactly as they said it. Do NOT summarize, paraphrase, condense, restructure, rewrite for clarity/flow/grammar, remove tangents/repetition/filler, add headings or bullet structure the user didn't provide, or add narrator framing ("Today Riley reflected on…"). The journal is a primary-source record of the user's own words. The ONLY editing allowed: sentence-ending punctuation + commas at clear speech pauses, paragraph breaks at natural topic shifts, capitalization, and unambiguous dictation-typo fixes (e.g. "their"/"there"). The `Title` is where summarization belongs — never let title-style condensation leak into the body. If the user explicitly asks for a summary ("just summarize this", "give me the gist"), summarize — otherwise the body is verbatim.
