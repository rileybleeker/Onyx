## Experiments: N-of-1 trials (2026-11-13)

Design, Riley's decisions and the build status are in `docs/experiment-framework.md` (Sections 13 and 12.1). **No trial is registered; starting one is Riley's action, never an agent's.** What exists:

- **Tables** (`sql/experiment_framework_schema.sql`, applied): `pds.experiments` (one pre-registered protocol per row), `pds.experiment_secrets` (the 32-byte seed), `pds.experiment_schedule` (one arm per behavioral day), `pds.experiment_days` (self-reported adherence and declared exclusions), view `pds.experiment_day_status` (past days only, with the objective Screen Time check). **Service role only** (RLS on, no policies, no grants to anon / authenticated), and the service role cannot remove rows. Trial adherence never goes in `pds.habit_journal` (a habit row would become a treatment in `causal_inference.py`), and the arm never enters the behavioral matrix.
- **Concealment is the point of the access model.** The schedule for the whole trial exists from registration, but the app can learn only today's arm: the single reveal is `pds.experiment_today()` (called by `lib/experiments-server.ts`, `server-only`), which returns the arm of `pds.behavioral_today_now()` and stamps `first_revealed_at` once. The check-in question's `pds.experiment_adherence_day()` repeats an arm only for today or yesterday and only once that stamp exists. The frontend calls these functions only, never a table. Never add a query on `experiment_schedule` or `experiment_secrets` to the frontend, never add `/api/experiments/*` to `isCiRoute()`, and never print a seed or an arm in a script (Actions logs are public). `frontend/tests/experiments.test.cjs` fails on each of these.
- **The protocol is locked at registration** (trigger `experiments_guard`): afterwards only the status (forward only), the stop fields and the Notion page id can change; seed and schedule never. One active trial at a time. A wrong registration is stopped and redone under a new id, not edited.
- **Libraries (pure, no I/O):** `experiment_design.py` (permuted blocks from PCG64's raw stream, seed commitment, protocol validation: MID of 8 ms or more, first day in the future, alignment version must equal `hrv_alignment.ALIGNMENT_VERSION`) and `experiment_analysis.py` (model with the carryover term, randomization test, interval by inversion, decision rule). `analyze_trial` raises `AnalysisNotAllowed` before the pre-registered end: do not add a way around it, and do not compute an effect on a running trial by any other route (Riley's decision 1).
- **Admin command:** `experiment_admin.py` (`seed`, `register`, `verify`, `stop`, `status`, `power`), run only through the manual workflow `experiment-admin.yml` on `master` (`gh workflow run experiment-admin.yml -f action=...`; the four steps to start a trial are in the doc, Section 12.1). Protocol files live in `docs/experiments/` (`TEMPLATE.md`; `EXP-000` can never be registered). Heartbeat `experiments|admin` on every write; a schedule that no longer matches its seed is a `GUARD experiment_schedule:` failure.
- **Today card.** When an N-of-1 trial is running, Today shows that behavioral day's arm and its instruction at the top (`GET /api/experiments/today`). With no trial registered, which is the usual case, nothing is rendered. The card has no buttons; opening Today records nothing about what Riley did.
- **Check-in question (2026-11-14).** While a trial runs, `/check-in` asks "Followed today's arm?" (Yes / Partly / No + an optional note) on the Today tab, and on the Yesterday tab for an answer given the next morning (`app/check-in/ExperimentAdherence.tsx`, `GET|POST /api/experiments/adherence`). Each tap saves at once (on its own, not through the check-in's answers) into `pds.experiment_days`, only through the database functions `pds.experiment_adherence_day()` / `pds.experiment_record_adherence()` (`sql/experiment_adherence_reports_schema.sql`). They answer only for a running trial, only for today or yesterday, and only for a day whose arm Today has already shown (`first_revealed_at`); otherwise "open Today to see today's arm" or nothing. The check-in never calls `/api/experiments/today` (only Today reveals). With no trial it renders nothing.
- **Report job (2026-11-14):** `experiment_report.py` (`--dry-run` is its only option; there is deliberately no `--as-of` / `--force`). With no trial it is a no-op with a success heartbeat. While a trial runs it writes PROGRESS counts only to `pds.experiment_reports` (days, nights with an outcome, missing share, adherence from `experiment_adherence.py`: the Screen Time check decides once settled, the check-in answer is the fallback) and never loads an HRV value; from the planned end + 2 days it writes the FINAL report once (the registered analysis plus covariate, Eight Sleep and resting-HR fits, flight / transition / declared-pause block exclusions, the seed reveal) and marks the trial complete. The table's guard refuses an effect in a progress row and a final row before the end. Heartbeat `experiments|report` on every run (`partial` = 3+ nights in a row without HRV or adherence under the protocol's `adherence.min_pct`); `GUARD experiment_alignment:` / `GUARD experiment_schedule:` are `failed`. `/status` has an **Experiments** card on that heartbeat (Unknown until the first run). The scheduled workflow (`.github/workflows/experiment-report.yml`, daily 15:00 UTC, env `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `NOTION_API_KEY`) and its `tools/watchdog_cloud.py` `SCHEDULED` line are in the held PR "[Riley merge] Experiment report schedule", merged by Riley after the SQL file is applied.
- **Notion mirror (2026-11-14):** `experiment_notion.py`, called by the report job through `experiment_report.Mirror`. One page per experiment in **"Onyx Experiments"** (data source `d99f3df8-6759-4de0-b9be-3761759ecd26`, under Project Onyx; doc 10.1): protocol fields + Status from registration on, progress counts while running (the progress writer cannot send an effect field), the effect fields and the "Report (auto)" toggle section only from the final report (replaced, never appended; Riley's own blocks stay). Found by `pds.experiments.notion_page_id`, else by title; two pages for one id are refused. Same secret and client conventions as the other Notion jobs (`NOTION_API_KEY`, httpx + `retry_helper.retry_http`, Notion-Version `2025-09-03` as in `tools/notion_tasks.py`). **Best-effort:** the Supabase row is written first; a Notion failure or a missing key turns the heartbeat `partial` (status + Notion error code only), and a final report that missed Notion is retried from the stored payload (`notion_synced_at` empty), never re-analysed. Not called with no trial registered or in `--dry-run`.
- **A/A check (2026-11-14):** protocol field `kind: aa` (default `treatment`). `validate_protocol` requires identical arms and no `adherence.objective` for `aa`, and two different arms for a treatment trial. `docs/experiments/EXP-900.md` is the 4-week check (7 blocks; **defined, not seeded or registered**; real trials count up from EXP-001, A/A checks from EXP-900). Its final report gets `aa_check` (no false effect at alpha, every day revealed, check-in answers on 90%+ of days); a check that does not pass turns that run's heartbeat `partial`. `aa_check` is one of the effect keys the report table's guard refuses in a progress row. Riley's steps: doc 12.2.
