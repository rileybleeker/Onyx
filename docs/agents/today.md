## Today home (2026-11-11)

`/` renders Today directly (no redirect; same static page) and the mobile Today tab opens `/today`. This read-only landing page shows up to three open agent request links in inbox order (not an urgency ranking), recorded reading progress, and links into the Log screen ("Start your check-in" opens `/log`; the quick links Supplement / Habit / Weight and "Open check-in" open `/log#log-part-<section>`, see Log screen). Informational messages stay in the Agents inbox; Status stays available. Loading, failure, empty and unknown progress states remain distinct. Fetch on mount, manual refresh and return to the app; stale requests cannot replace newer results. Opening Today never sends a reply, marks anything read or logs a behavior. Reuse the existing authenticated inbox and reading endpoints, and keep personal record data out of review prompts and fixture tests.

**Overview: the whole app in one scroll (2026-11-14, `components/overview/`, `lib/overview-cards.ts`, `lib/overview-views.ts`).** Under Today's own panels (which stay first and unchanged) one card per area: recovery + tonight's HRV forecast, sleep, activity + steps, nutrition + caffeine, supplements, habits + reading, money (alerts + renewals, no amounts), orders, calendar + care, screen time, agents, NYC search, status, and "More pages" (every `lib/nav.ts` page no card covers, so a new page is listed the day it is added; a card of its own = an entry in `OVERVIEW_CARDS` + its sources in `components/overview/sources.ts` + its view in `lib/overview-views.ts`). Each card: up to 3 numbers, one small hand-drawn SVG chart or 2 lines, an Open link; one fixed height (272 px) shared with its skeleton and error state, so nothing moves. Speed: the overview is its own chunk (`TodayOverview.tsx`, `ssr:false`), a card reads only within 600 px of the screen (one IntersectionObserver) and mounts its body through `DeferredMount` (new `placeholder` prop); reads are existing GET endpoints and small `lib/queries` reads (7-9 days) through the client cache, URL keys shared with Today and the pages (a card waits up to 2.5 s for Today's own fetch of a shared key instead of asking twice), and the cards further down are read one per idle slot (10-minute freshness; also added to the warm-up's `/today` reads, memory-only and Today's own keys excluded). Privacy: finance and procurement come only from `/api/finance/alerts` and `/api/procurement/renewals/summary`, screen time only from the new `GET /api/screen-time/summary` (numbers only, service role via `lib/screen-time-server.ts`, owner session, not in `isCiRoute()`), all memory-only in the cache; care items memory-only too; medical records and the experiment arm are never read (link only). **Edit** (one self-contained component, `OverviewEditor.tsx`, ready to move onto a shared Personalize framework): a draft of the order with show / hide, drag by the grip on a mouse (accent insertion marker where the card will land), up / down buttons on the phone and for the keyboard (44 px), Reset to default, Cancel, Done. Only Done writes: the arrangement `{v: 1, order, hidden}` goes to `PUT /api/ui/preferences` under `overview.cards`, so phone and desktop match (re-read when the app returns after a minute); `mergeArrangement` keeps a saved order valid as cards are added or removed. Opening Today still writes nothing. Tests: `frontend/tests/overview-cards.test.cjs`; `tests/today-regression.cjs` renders the overview as nothing.

**Urgent email (2026-11-11).** Email only; text messages stay disabled. inbox-triage (personal-agents) decides what is urgent; Today only shows it. Two sources, merged into one list by `mergeUrgent` in `lib/urgent-email.ts`: (1) threads it labelled `Agent/Action` or `Agent/Deadline`, copied hourly by `urgent_email_etl.py` into `pds.inbox_emails` (service-role only; subject, sender, times, labels, flags and a ≤240-char snippet that never leaves the server) and served by `GET /api/urgent-email` (`lib/urgent-email-query.ts`: one item per thread; archived threads, Action older than 14 days, deadlines already passed or more than 7 days out, and undated Deadline mail older than 3 days are left out); (2) its `Urgent: …` Agent Inbox questions from `/onyx/inbox` (any card whose link is a Gmail URL counts too). A card whose link names a labelled thread (`#all/thread-f:<X-GM-THRID>`, same account) merges into that item, and the same Message-ID in both mailboxes shows once; email cards are listed under Urgent email, not under Needs your input. A card whose link is only a Gmail `#search/…` merges into the ONE labelled email of the same account, received in the 7 days before the card, that the search would find judged on subject and sender (`gmailSearchTerms` + `searchMatchesEmail`: each plain word in the subject or the sender's display name, or the domain labels when there is no name, never the address local part; `subject:` / `from:` / quoted phrases / `-` exclusions honoured, other operators ignored); two candidates = no merge. Each item shows its source, age and the label sync's age, why it is shown, and the next step, with an `Open in Gmail` link (mail.google.com only) and/or `Open request`. Until `sql/inbox_emails_schema.sql` is applied the API answers `not_connected` and Today says the label sync is not connected. `/status` card **Urgent Email** (badge GMAIL) = `urgent_email|labels` heartbeat age: >3 h degraded, >8 h or a failed run red. Tests: `frontend/scripts/test-urgent-email.mjs`, `tests/test_urgent_email_etl.py`, `tests/today-regression.cjs` (synthetic fixtures only).

## Clearing (was filed under Procurement)

**Clearing (2026-11-14, `lib/today-clear.ts`).** "Needs your input" and "Urgent email" each have an × per row and a **Clear all** (every item the panel knows about, not only the rows on screen), then an 8-second **Undo** bar. Opening Today still clears nothing; only a tap does. Agent Inbox cards (requests, and inbox-triage questions merged into an urgent item: `TodayUrgentItem.clear.cards`) go through the Worker's `POST /onyx/dismiss`, the same call as the Agents inbox's Clear (the card leaves Unread and the badge; the agent still waits for an answer; Today also closes the phone's notifications). Labelled threads (`clear.emails`, including the same message's copy in the other mailbox) go to **`POST /api/urgent-email/clear`** (`{items: [{key, receivedAt}]}`, `undo: true` to bring them back; owner session only, never add it to `isCiRoute()`; same-origin JSON, 16 KB cap; logs a database code only) → **`pds.today_cleared_emails`** (`sql/today_cleared_emails.sql`, applied; service-role only; SHA-256 of the thread key + the newest message time cleared). `getUrgentEmail` leaves a cleared thread out (counted as `cleared`) until a NEWER message arrives in it, and shows everything if that read fails. Nothing is sent to Gmail: no label, read flag or archive change. Cleared rows stay hidden on screen while the servers catch up; a failed clear puts the row back with a message. Tests: `frontend/tests/today-clear.test.cjs`, `frontend/scripts/test-urgent-email.mjs`, `tests/today-regression.cjs` (`lib/today-clear.ts` is import-free and bundled by name there; the regression transpiles Today to ES5, so use `Array.from`, not spread, on a Set or Map).

## Calendar (was filed under Procurement)

**Calendar (2026-11-13).** A panel after Urgent email lists today's and tomorrow's Google Calendar events (read-only copies from `pds.calendar_events`, see the Google Calendar bullet under Database): all-day first, then by start time, times in the browser's zone, with the calendar label, "Tentative" where the calendar says so and the location; at most six per day. One `GET /api/calendar/events?from=<local today>&to=<local tomorrow>` per load, inside the same sequence guard as the other panels. Not connected (table missing, or no sync run and no events), an empty day, a failed check and a failed refresh (keeps the last list) are four different states; a sync older than 3 h or not `success` is flagged. The only link goes to `/health`. Helpers are value-imported from the import-free `lib/calendar-events.ts`, which `tests/today-regression.cjs` bundles by name (register any new value import there); the test's fetch mock answers the calendar URL at once and keeps it out of `window.calls` / `window.pending`.
